# Windows Event Log Cleared (SOC130)

## Overview

This investigation analyzes a **Windows Event Log Cleared** alert generated by the EDR. The alert suggested that Windows event logs may have been cleared, a technique commonly associated with **anti-forensics (MITRE ATT&CK T1070.001)**. The objective of the investigation was to determine whether the activity was malicious or a false positive.

---

## Alert Details

| Field | Value |
|-------|-------|
| Rule | SOC130 - Event Log Cleared |
| Severity | Medium |
| Category | Malware |
| Event ID | 64 |
| Source Host | Exchange Server |
| Source IP | 172.16.20.3 |
| Username | Administrator |
| File Name | powershell.exe |
| File Size | 437.5 KB |
| Device Action | Allowed |

---

## Investigation Steps

- Reviewed the alert details and associated endpoint information.
- Verified that the source IP **172.16.20.3** belongs to the Exchange Server.
- Checked the available logs within the investigation timeframe.
- Analyzed the provided `powershell.exe` artifact.
- Verified the executable's hash using **VirusTotal** and **ANY.RUN**.
- Searched for additional Indicators of Compromise (IOCs).
- Correlated the findings with the alert context and endpoint activity.

---

## Findings

- No suspicious events were identified within the available logs.
- The source IP **172.16.20.3** was confirmed to belong to the Exchange Server.
- The PowerShell process was executed under the **Administrator** account, which is common for Exchange Server administration and maintenance tasks.
- The executable showed **no malicious reputation** on VirusTotal or ANY.RUN.
- No additional Indicators of Compromise (IOCs) were identified.
- Although the alert indicated Windows Event Log clearing, the available evidence was insufficient to confirm malicious log tampering or attacker activity.

## Verdict

**False Positive**

The investigation did not identify evidence of malicious activity. The PowerShell executable had **no malicious reputation**, no additional indicators of compromise were found, and the process was executed under the **Administrator** account on the Exchange Server, where PowerShell is routinely used for legitimate administrative and maintenance operations. Based on the available evidence, the alert was classified as a **False Positive**.

---

## Recommendations

- Verify that the associated executable has been quarantined or removed if required.
- Continue monitoring PowerShell activity executed by privileged accounts.
- Correlate future **Event Log Cleared** alerts with **Windows Security Event ID 1102**, PowerShell logs, and EDR telemetry.
- Establish a baseline for legitimate administrative PowerShell usage on critical servers to reduce future false positives.
